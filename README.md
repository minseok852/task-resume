# 작업 맥락 저장·복귀 확장

**중단할 때 다음 행동과 시작 탭을 남기고, 돌아오면 그 지점부터 이어가는 Chrome 확장 프로그램입니다.**

> 개발 2일차 기록 · 2026-10-29  
> 로컬 저장·작업 관리·복귀 흐름을 구현하고 오류 처리와 접근성을 보완하는 중입니다. 실제 Chrome 검증과 사용성 확인은 진행 중입니다.

## 왜 만들었나요?

과제와 개발 학습을 번갈아 하다 보면 브라우저 자료는 남아 있어도 무엇을 하려던 것인지 다시 파악해야 합니다. 이 프로젝트는 탭 목록에 **돌아와서 할 일 한 줄**과 **시작할 탭**을 함께 남겨 복귀 부담을 줄일 수 있는지 살펴봅니다.

예를 들어 다음과 같이 작업을 남깁니다.

| 항목 | 예시 |
| --- | --- |
| 작업명 | 자료구조 과제 |
| 다음 행동 | 예제 3의 시간복잡도 확인하기 |
| 시작 탭 | 예제 3이 있는 문서 |
| 참고 자료 | 강의 자료와 관련 문서 |

다음 행동은 선택 입력입니다. 비워둔 메모를 AI로 추론하지 않습니다. 기존 탭 관리 도구보다 낫다는 것은 아직 검증하지 않은 제품 가설입니다.

## 사용 흐름

1. **지금 작업 · 이어갈 지점 남기기**를 눌러 현재 일반 창의 탭을 읽습니다.
2. 작업명과 다음 행동을 적고, 필요한 탭과 시작 탭을 선택해 저장합니다.
3. 나중에 작업 목록에서 **이어서 할 일 확인**을 누릅니다.
4. 하려던 일을 확인하고 **이어서 시작**을 누르면 시작 탭으로 이동합니다.

같은 주소가 이미 열려 있으면 가능한 경우 기존 탭을 재사용합니다. 참고 자료는 기본적으로 접혀 있으며 사용자가 선택한 것만 별도로 엽니다. 작업 화면에 들어오는 것만으로 탭을 자동 복원하거나 기존 탭을 닫지 않습니다.

## 구현한 기능

- 현재 창 탭 조회, URL 중복 병합, 탭 선택과 시작 탭 지정
- 로컬 작업 저장·목록·이름/메모/선택 탭/순서/시작 탭 수정
- 현재 창의 탭으로 기존 작업 갱신: 미리보기와 교체 확인
- 화면 내 확인을 거치는 작업 삭제
- 다음 행동 중심 복귀 화면, 시작 탭 이동, 참고 탭 선택 열기
- 저장 실패 시 입력 유지, 데이터 형식 검사, 변경 충돌 감지
- 처리 중 선택 잠금, 확인 취소·화면 전환 후 포커스 이동, 오류 표시 분리

## 로컬에서 실행하기

별도 빌드나 패키지 설치가 필요하지 않습니다.

1. 저장소 파일을 내려받아 압축을 풉니다.
2. Chrome에서 `chrome://extensions`에 접속합니다.
3. **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누르고 `manifest.json`이 있는 폴더를 선택합니다.
5. 확장 아이콘을 눌러 **중단한 작업 이어가기** 화면을 엽니다.

코드 변경 후에는 확장 관리 화면에서 해당 확장의 새로고침(↻)을 누르고 팝업을 다시 여세요. 설치와 권한 승인은 사용자가 직접 진행합니다. Chrome Web Store에는 등록하지 않았으며, 로컬 실행과 스토어 심사는 별개입니다.

## 기술 구성

Manifest V3, HTML, 기본 CSS, JavaScript ES Modules를 사용합니다. 서버·DB 서버·로그인·빌드 도구 없이 시작했습니다.

```text
manifest.json       확장 메타데이터와 권한
popup.html/css      팝업 화면과 스타일
popup.js            화면 상태와 사용자 이벤트
src/model.js        URL·선택·입력 검증 규칙
src/storage.js      저장소 검증과 저장·수정·삭제
src/tabs.js         탭 조회·열기·재사용
src/render.js       DOM 생성과 텍스트 출력
test/               순수 규칙 및 모의 통합 테스트
scripts/verify.mjs  구문·파일 참조·manifest 정적 검사
```

## 권한과 데이터 보관

| 권한 | 사용 목적 |
| --- | --- |
| `tabs` | 현재 창 탭의 제목·URL 조회 및 복귀 시 기존 탭 검색 |
| `storage` | 작업을 `chrome.storage.local`에 보관 |

`tabs` 권한 자체는 현재 창에만 한정되지 않습니다. 저장 후보는 현재 창에서 읽고, 복귀 시에는 다른 일반 창의 동일 URL 탭도 찾습니다. 웹페이지 본문·폼 입력은 읽지 않습니다. host permissions, content script, background worker는 사용하지 않습니다.

작업 URL·제목·메모를 자체 서버로 전송하거나 동기화하지 않습니다. 다만 URL에는 검색어·문서 식별자 같은 개인정보가 포함될 수 있고, 로컬 저장소는 암호화 보관함이 아닙니다. 민감한 탭은 선택에서 제외하세요. 확장 삭제 시 데이터가 사라질 수 있습니다.

HTTP/HTTPS 주소만 지원하며 Chrome 내부 페이지, 파일 주소, 시크릿 탭 등은 제외합니다. 탭의 영속 식별에는 Chrome tabId 대신 자체 UUID를 사용합니다.

공식 문서: [Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs), [Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage).

## 테스트와 현재 한계

Node.js가 있으면 다음 명령으로 검사할 수 있습니다. 개발 환경은 Node.js 24이며 추가 의존성은 없습니다.

```sh
node --test
node scripts/verify.mjs
```

현재 자동 테스트 **25개**와 정적 검사가 통과한 상태입니다. 순수 규칙, 메모리 Chrome API, 모의 DOM을 이용해 저장 실패·입력 보존·반복 클릭·편집 충돌·삭제·복귀·선택 잠금·포커스 흐름 등을 확인합니다. 자동 테스트는 사용자 브라우저 저장소를 초기화하지 않습니다.

이 결과가 실제 브라우저의 모든 동작을 보장하지는 않습니다. 실제 Chrome에서의 레이아웃·키보드 탐색·두 창 사이 포커스·재시작 후 데이터 유지 확인과 실제 과제 사용성 검증이 남아 있습니다.

- 팝업을 닫으면 미저장 입력은 사라집니다. 저장 완료 표시를 확인하세요.
- 충돌이나 저장 결과 확인 실패가 나오면 입력을 별도로 적어두고 **목록 다시 읽기**로 확인합니다.
- 저장 전 최신 데이터 비교와 지원 환경의 Web Locks를 사용하지만, 외부에서 저장소를 직접 변경하는 경우까지 완전한 동시 편집을 보장하지 않습니다.
- 로그인, 서버, 동기화, 협업, AI, 폼 입력·스크롤 복원은 현재 범위에 없습니다.

실제 과제 두 개를 중단·복귀하면서 저장 부담과 첫 행동까지 걸리는 시간을 살펴보고, 기존 탭그룹+메모 방식과 비교할 예정입니다. 현재 수요나 생산성 향상을 검증했다고 주장하지 않습니다.
